# IssueFlow

IssueFlow is a full-stack issue tracking application built with React,
TypeScript, Express, and PostgreSQL. It allows users to create, update,
search, filter, sort, and delete issues through a responsive dashboard backed
by a REST API and persistent PostgreSQL storage.

## Features

- Create issues with configurable priority levels
- Update issue titles, priorities, and workflow status
- Delete issues
- Search issues by title
- Filter issues by status
- Sort issues by newest, oldest, title, or priority
- View dashboard summaries for total, todo, in-progress, and completed issues
- Persistent PostgreSQL data storage
- RESTful Express API
- Server-side request validation
- Automated unit and API integration tests
- Dockerized PostgreSQL development environment

## Architecture

```text
React Client
     |
     | HTTP / JSON
     v
Express REST API
     |
     v
Route Layer
     |
     v
Repository Layer
     |
     v
PostgreSQL
```

The backend is separated into focused modules:

```text
server/src/
├── app.ts
├── db.ts
├── index.ts
├── types.ts
├── validators.ts
├── repositories/
│   └── issues.ts
└── routes/
    ├── health.ts
    └── issues.ts
```

The route layer handles HTTP requests, validation, and responses, while the
repository layer contains PostgreSQL queries and database operations.

## API

### Get all issues

```http
GET /api/issues
```

### Create an issue

```http
POST /api/issues
```

Example request:

```json
{
  "title": "Fix login bug",
  "priority": "High"
}
```

### Update an issue

```http
PATCH /api/issues/:id
```

The API supports partial updates.

Example:

```json
{
  "status": "Done"
}
```

or:

```json
{
  "title": "Fix authentication bug",
  "priority": "Medium"
}
```

### Delete an issue

```http
DELETE /api/issues/:id
```

### Health check

```http
GET /api/health
```

The health endpoint verifies connectivity between the Express server and
PostgreSQL.

## Database

Issues are stored in PostgreSQL using the following core fields:

```text
id
title
status
priority
created_at
updated_at
```

Issue IDs are generated by PostgreSQL.

Valid statuses:

```text
Todo
In Progress
Done
```

Valid priorities:

```text
Low
Medium
High
```

Database queries use PostgreSQL parameterized queries to avoid directly
interpolating user input into SQL statements.

## Testing

IssueFlow includes both unit and integration testing.

Unit tests cover validation utilities.

API integration tests exercise the application across:

```text
HTTP request
    ↓
Express
    ↓
Route
    ↓
Repository
    ↓
PostgreSQL test database
```

The integration suite covers core CRUD behavior and invalid request cases.

Run the tests:

```bash
cd server
npm test
```

Run test coverage:

```bash
npm run coverage
```

Run TypeScript checking:

```bash
npm run typecheck
```

Tests use a dedicated `issueflow_test` PostgreSQL database so test operations
do not modify development data.

## Local Development

### Prerequisites

Install:

- Node.js
- npm
- Docker
- Docker Compose

### Clone the repository

```bash
git clone YOUR_REPOSITORY_URL
cd issue-flow
```

### Install frontend dependencies

```bash
npm install
```

### Install backend dependencies

```bash
cd server
npm install
cd ..
```

### Configure environment variables

Create:

```text
server/.env
```

using:

```text
server/.env.example
```

as a template.

Example configuration:

```env
POSTGRES_DB=issueflow
POSTGRES_USER=issueflow
POSTGRES_PASSWORD=your_password

PGHOST=localhost
PGPORT=5432
PGDATABASE=issueflow
PGUSER=issueflow
PGPASSWORD=your_password
```

Do not commit `.env`.

### Start PostgreSQL

From the project root:

```bash
docker compose up -d
```

### Start the backend

```bash
cd server
npm run dev
```

The API runs at:

```text
http://localhost:3001
```

### Start the frontend

In another terminal from the project root:

```bash
npm run dev
```

Open the local URL displayed by Vite.
